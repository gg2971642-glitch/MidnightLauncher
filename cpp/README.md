# Midnight launcher на C++

C++-версия лаунчера: Win32 + Direct2D/DirectWrite.

## Этап 1 — готово (оболочка)

- окно 1180×740 по центру экрана, тёмная тема, тёмный заголовок Windows;
- сайдбар: логотип-иконка (`midnight.png` в скруглённой плитке), «MIDNIGHT / LAUNCHER», 4 пункта меню, карточка аккаунта;
- страницы: Главная, Моды, Каталог, Настройки;
- анимация перехода (сдвиг + прозрачность, 60 кадров/с);
- вся отрисовка — одним кадром Direct2D/DirectWrite;
- DPI-aware (PerMonitorV2).

## Этап 2 — готово (каталог и установка)

- сеть на WinHTTP, JSON на nlohmann/json (header-only, `third_party/json.hpp`);
- **Modrinth**: популярное и поиск, вкладки модов / ресурспаков / шейдеров / датапаков,
  фильтр «Как в сборке» (ядро + версия MC из профиля);
- иконки проектов грузятся в фоне (WIC → D2D-битмап), список прокручивается колесом;
- поиск: поле ввода с кареткой, Enter, Backspace, Esc, Ctrl+V;
- установка в папки выбранной сборки:
  - моды → `mods`,
  - ресурспаки → `resourcepacks`,
  - шейдеры → `shaderpacks`,
  - датапаки → `saves\<самый свежий мир>\datapacks` (именно `.zip`, Paper-плагины отсекаются);
- прогресс скачивания в кнопке (%), статус-строка внизу;
- страница «Моды» показывает реальные `.jar` из профиля;
- «Главная» показывает профиль, ядро, версию и число модов.

Проверено на профиле «Тест» (Fabric 1.20.1): установлены Sodium,
Fresh Animations, Complementary Reimagined, датапак VeinMiner (zip в мир).

## Этап 3 — готово (сборки и запуск)

- все профили из `nexus\profiles.json` — список сборок на «Главной», переключение кликом;
- запуск игры кнопкой «Играть»:
  - version JSON с разворачиванием `inheritsFrom` (Fabric/Quilt/Forge/NeoForge поверх ванили);
  - проверка и докачка клиентского jar, библиотек, индекса ресурсов и объектов assets
    (8 потоков, прогресс в карточке);
  - распаковка нативов в `versions\<версия>\natives` (через системный `tar.exe`);
  - поиск Java: путь из настроек → рантайм Mojang в `runtime\<component>\windows-x64`
    → установленная Java (по `release`/`java -version`) → автоскачивание рантайма Mojang;
  - аргументы JVM/игры из version JSON с подстановкой плейсхолдеров и учётом `rules`;
    для Forge добавляется клиентский jar в `-DignoreList`;
  - запуск без консольного окна, cwd = папка сборки, `-Xms`/`-Xmx` из `settings.json`;
- лог запуска на «Главной»: шаги подготовки + stdout/stderr игры, кнопка «Очистить»;
- кнопка «Остановить» завершает процесс игры; выход из лаунчера игру не закрывает;
- после запуска показываются найденная Java и её версия; в настройках — Java и память.

Важно: моды **не** добавляются в classpath — Forge падал с `module.ResolutionException`,
загрузчики сами читают папку `mods`.

Проверено: «Тест» (Fabric 1.20.1, 77 модулей Fabric API + Sodium) и
«Create» (Forge 1.20.1, 22 мода) — обе доходят до главного меню, «Остановить» убивает процесс.

## Этап 4 — готово (авторизация)

- карточка аккаунта в сайдбаре кликабельна: показывает ник, провайдера и «онлайн»;
- вход через **Microsoft** по коду устройства (`login.live.com`):
  код и ссылка `microsoft.com/link`, ожидание подтверждения, прогресс;
  далее Xbox Live → XSTS → `login_with_xbox` → проверка лицензии → профиль;
- вход через **Ely.by** (ник/e-mail и пароль, поддержка `пароль:код` при 2FA);
- меню «Аккаунты»: переключение Microsoft ↔ Ely.by без повторного пароля,
  добавление второго аккаунта и выход;
- токены хранятся в `%APPDATA%\.minecraft\nexus`:
  `auth.json`, `ely.json`, `account.txt`; при старте сессии тихо продлеваются;
- запуск игры с онлайн-аккаунтом: `--username`, `--uuid`, `--accessToken`,
  `--userType msa` (Microsoft) или `mojang` (Ely.by);
- для Ely.by скачивается `authlib-injector.jar` и добавляется
  `-javaagent:...=https://authserver.ely.by/api/authlib-injector`;
- без входа игра запускается офлайн (`Player`, `legacy`), как раньше.

Проверено: загрузка сохранённого аккаунта из `auth.json`, получение реального кода
устройства Microsoft, окна входа и меню аккаунтов, ответ Ely.by на неверные данные.
Запуск «Тест» с тестовым аккаунтом передал в Java `--userType msa`, UUID и непустой токен.

## Этап 5 — готово (настройки и оформление)

- тёмная и светлая темы, палитра пересчитывается на лету (`ApplyPalette`),
  значения тем (`THEMES`);
- основной и второстепенный цвет: 6 пресетов, поле `#RRGGBB` и «ок»;
  применяются сразу, как и тема (заголовок окна тоже переключается);
- страница «Настройки» — реальные поля с вводом: память (мин/макс), путь к java,
  кнопка «Проверить Java», имя игрока, доп. аргументы Java и игры;
  прокрутка колесом, индикатор прокрутки;
- фокус ввода: клик по полю, `Tab`/`Shift+Tab`, `Backspace`, `Ctrl+V`, `Esc`,
  `Enter` в поле цвета — применить;
- запись `nexus\settings.json` с сохранением незнакомых ключей (`fullscreen`);
- свой шрифт **Inter** из `resources\fonts` (кастомная коллекция DirectWrite,
  `AddFontResourceExW` + `IDWriteFactory3`), иначе системный из стека;
- иконка приложения встроена в exe (`src\app.rc.in`, id 1) — видна в Проводнике,
  на панели задач и в заголовке окна; если ресурса нет, берётся
  `resources\midnight.ico` рядом с exe; свой AppUserModelID `MidnightLauncher`;
- ресурсы ищутся рядом с exe: `resources\<имя>`, затем `<имя>`.

Проверено: тёмная ↔ светлая тема, акценты `#00C2A8`/`#FFA53D`, ввод в поля,
`settings.json` после round-trip = `theme dark, accent #7C5CFF, accent2 #FF6B9A,
fullscreen false` (значения пользователя восстановлены).

### Смена скина и плаща

- кнопка «Сменить скин» в карточке аккаунта открывает встроенную страницу
  (без отдельного окна, как `open_view`), «← Назад» возвращает;
- предпросмотр: скин рисуется программно, как `render_skin` — спереди,
  голова/тело/руки/ноги со слоями-оверлеями, поддержка старых 64×32,
  тонкая модель (`slim`) и классическая; масштаб ×8, PNG-текстура 64×64;
- «Свой файл…» — системный диалог PNG, модель определяется автоматически
  (`skin_is_slim`), выбор можно поправить переключателем;
- «Скин другого игрока» — ник → официальные API Mojang
  (`lookup/name` → `session/minecraft/profile` → base64 `textures`),
  иначе Ely.by (`skinsystem.ely.by/textures`), затем «Поставить скин»;
- загрузка/сброс: Microsoft — `POST /minecraft/profile/skins` и
  `DELETE .../skins/active`; Ely.by — `PUT/DELETE .../user/profile/<id>/skin`
  (`multipart/form-data`, `Authorization: Bearer`);
- плащи: список из профиля, активный помечен «✓», «Не носить» — `DELETE`;
  без плащей карточка скрыта;
- аватарка в сайдбаре — настоящая голова скина (круглая маска), а не буква:
  активный скин подтягивается в фоне при запуске/входе (профиль по токену,
  при истёкшем токене — по нику через публичные API Mojang/Ely.by);
  если скина нет — остаётся первая буква ника;
- тексты ошибок: 401 «сессия истекла…», 403, 404, 429, 400.

Проверено: открытие страницы, предпросмотр чужого скина по нику `Notch`,
переключение Steve/Alex, голова в сайдбаре, «Назад», диалог выбора файла
и понятная ошибка при истёкшем токене (`401` → «сессия истекла…»).

## Этап 6 — готово (создание сборок, выбор сборки, Java)

- кнопка «+ Новая сборка» на «Главной»: имя, версия Minecraft и ядро
  (Vanilla / Fabric / Quilt / Forge / NeoForge); окно — оверлей поверх страницы;
- сразу после «Создать» создаётся папка `profiles\<имя>` с `mods`, сборка пишется
  в `nexus\profiles.json`, и в фоне **скачивается версия**: клиентский jar,
  библиотеки, индекс ресурсов и objects, распаковка нативов; прогресс и шаги — в карточке и логе;
- версия ядра подбирается сама:
  Fabric/Quilt — первая стабильная из meta, Forge — `-recommended` (затем `-latest`)
  из `promotions_slim.json`, NeoForge — последняя с префиксом версии MC из maven;
- Fabric/Quilt ставятся JSON-профилем из meta; Forge/NeoForge — официальным
  installer jar (`--installClient`), с созданием `launcher_profiles.json` при необходимости
  и автоскачиванием нужной Java;
- если создать не удалось — сборка убирается из списка, причина в статус-строке;
- «Установить» в каталоге открывает окно «Куда установить?» со списком сборок:
  для модов показываются только совместимые (Modrinth `game_versions` + `loaders`);
  если проверить нельзя (нет сети) — предупреждение, список не скрывается;
- настройки, карточка Java: «Обзор…» выбирает `java.exe` (сразу пишется в `java_path`),
  чипы Java 8/17/21/25 скачивают рантайм Mojang в `runtime\...` с прогрессом
  и подставляют путь; «Проверить Java» — как раньше.

Проверено автотестом (клики сообщениями Windows, временный `%APPDATA%` с junction на файлы игры):
создание Vanilla 1.20.1, Fabric 1.20.1 (loader 0.20.1), Quilt 1.20.1 (0.24.0),
Forge 1.20.1 (47.4.28), NeoForge 1.21.11 (21.11.48); скачивание Java 17 с записью пути;
меню установки для Fabric API показало только Fabric-сборку (Forge скрыта) и поставило мод в неё.

### Страница проекта в каталоге

- клик по строке каталога открывает страницу проекта, а не браузер: иконка, название,
  автор, скачивания/подписчики, лицензия, категории и версия под выбранную сборку;
- описание Modrinth (Markdown) выводится блоками: заголовки, абзацы, списки, код
  и цитаты; HTML-теги, ссылки и маркеры оформления убираются;
- скриншоты из галереи Modrinth (до 6) грузятся в фоне; клик открывает просмотр
  в области контента, закрытие — клик или `Esc`;
- дерево зависимостей: обязательные и опциональные зависимости выбранной версии
  (с учётом ядра и версии MC профиля), рекурсия по обязательным до 3 уровней,
  защита от циклов, не более 18 узлов; зависимости без подходящей версии помечаются;
- «Установить» со страницы открывает обычный выбор сборки, «Открыть на Modrinth»
  ведёт в браузер, «← Назад» и `Esc` возвращают каталог.

Проверено: Fabric API (описание без скриншотов и зависимостей), Iris Shaders
(4 скриншота с подписями, дерево `└─ Sodium`, лайтбокс), Entity Culling
(дерево `└─ Fabric API`, установка из страницы, `Esc`/«Назад»).

### Удаление сборки и дерево зависимостей в «Модах»

- у каждой сборки на «Главной» есть кнопка `✕`: открывается подтверждение
  «Удалить сборку?» с именем; «Удалить» удаляет, «Отмена», `Esc` или клик вне
  окна закрывают его без изменений;
- при подтверждении папка сборки (`game_dir`, только внутри
  `.minecraft\profiles`) удаляется вместе с модами и мирами, запись убирается
  из `nexus\profiles.json`; если игра этой сборки запущена — удаление запрещено;
  после удаления выбирается соседняя сборка, список модов и дерево обновляются;
- страница «Моды» показывает над списком файлов **дерево зависимостей**
  установленных модов: файлы опознаются по SHA-1 через `POST /v2/version_files`,
  названия и обязательные зависимости — через `GET /v2/projects`;
- у каждого установленного мода — его обязательные зависимости (до 4 уровней,
  защита от циклов), отсутствующие помечаются жёлтым «не установлен»,
  неопознанные — «нет данных Modrinth»; кнопка «Обновить» пересобирает дерево;
- список файлов и дерево прокручиваются колесом, шапка раздела закреплена.

Проверено: подтверждение и реальное удаление временной сборки (папка и запись
исчезли), отмена по «Отмена»/`Esc`; дерево «Тест» (AppleSkin → Fabric API,
Fabric API, Fabric Language Kotlin, Mod Menu, Sodium), дерево «Create»
(22 мода Forge, `Create: Steam 'n Rails` → `Create`), отсутствующая Fabric API
помечена «не установлен», прокрутка и «Обновить».

### Обзор сборки

- на карточке текущей сборки есть кнопка «Обзор сборки»: открывается окно
  с именем, ядром и версией, путём к папке, четырьмя плитками (всего, моды,
  миры, прочее) и разбивкой по папкам;
- список модов показывает все `.jar` с размерами и прокручивается колесом;
  количество файлов и общий размер считаются по папке сборки;
- «Открыть папку» запускает Проводник на папке сборки, «Открыть «Моды»» ведёт
  на страницу с деревом зависимостей, «Закрыть», `Esc` или клик вне окна
  закрывают обзор.

Проверено: «Тест» (6 модов, 68,7 МБ) и «Create» (22 мода, 117,6 МБ), прокрутка
списка, переход на «Моды» и закрытие окна.

## Языки интерфейса — готово

- шесть языков: русский (по умолчанию), английский, французский, немецкий,
  китайский и японский; выбор — в «Настройках» в карточке «Язык»;
- язык сохраняется в `nexus\settings.json` под ключом `language` и применяется
  сразу, без перезапуска: меняются тексты, локаль DirectWrite, шрифт и заголовки
  системных диалогов;
- переводятся только строки интерфейса и сообщения лаунчера; имена сборок,
  аккаунтов, модов, пути, поисковые запросы и другой пользовательский ввод
  остаются как есть;
- для китайского используется `Microsoft YaHei UI`, для японского — `Yu Gothic UI`
  (с системными fallback), поэтому иероглифы отображаются без «квадратов»;
- динамические статусы и логи переводятся по точному совпадению и по известным
  фрагментам, поэтому строки вида «Сборка «…» создана» тоже локализованы.

Проверено: переключение ru/en/fr/de/zh/ja на главной и в настройках, сохранение
выбора после перезапуска, китайские и японские шрифты, перевод строки загрузки
Java и статуса каталога.

## Сборка

Тулчейн (уже установлен):

- MinGW-w64 16.2 (UCRT, posix-seh): `%LOCALAPPDATA%\opencode-tools\mingw64\bin`
- CMake 4.4 + Ninja (в тестовой среде — pip-пакеты)

```
.\cpp\build.ps1
```

Результат: `cpp\build\MidnightL.exe` (~4,4 МБ, только системные DLL).

Ручная сборка одним вызовом g++:

```
g++ -std=c++20 -O2 -municode -mwindows -DUNICODE -D_UNICODE -DNOMINMAX ^
    -DWIN32_LEAN_AND_MEAN -DWINVER=0x0A00 -D_WIN32_WINNT=0x0A00 ^
    src/main.cpp -o build/MidnightL.exe ^
    -ld2d1 -ldwrite -ldwmapi -lole32 -luuid -lwinhttp -lwindowscodecs ^
    -lshlwapi -lshell32 -lcomdlg32 -lbcrypt -static -static-libgcc -static-libstdc++
```
